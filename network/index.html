user.sgit.ai / the network

The network

This site is one of a family of focused sites under sgit.ai, each pursuing one question further than a section of the parent could, each with its own version history and repository, and each linking rather than duplicating. This site owns the client-side user: the account with no server, the workflows a user runs in their browser, and the billing that follows. It borrows everything else.

Who owns what

SiteOwnsHow this site uses it
sgit.aiThe parent project: the vault layer, the CLI, the platform documentation, the three surfaces, the guidance for site pages.The substrate every workflow runs on, and the guidance this site was built to.
newsroom.sgit.aiPay for what you read; the vault pane; the passkey lab; the meter.Where every workflow marked runs actually runs. This site describes; the newsroom does.
pki.sgit.aiA key registry for agents and people, designed from the 2019 keyserver failure.The register the upload server checks a key against; where the admin's and the user's public keys would be published.
secrets.sgit.aiMoving a secret from A to B on public keys only; a vault for the private key; the keyring design.One of the two ways named for one account across sites: a key hub that holds the master and hands a site only the key to its own vault.
subscriptions.sgit.aiA subscription is a discount for regular use, not rent.The commercial model a billing vault would meter against; and the repository this site's build tooling was copied from.
llms.sgit.aiCalling a language model from a vault app with no API key.The pattern for what an agent gets from a user: a key for one purpose, never the master.
nhi.sgit.aiIdentity for agents you run and agents you rent.Why agents do not have passkeys, and get read keys instead.
api.send.sgit.aiThe API behind the vault server, and the rule of independent releases.The rule any api.user.sgit.ai would follow: every release a complete, independent copy at its own versioned path.
coding.sgit.aiHow the code across the family is written.Followed by this site's build tooling and the lab's code.

Where this site sits

The billing article left the question open: user.sgit.ai with api.user.sgit.ai, or billing.sgit.ai with api.billing.sgit.ai so that others can use it easily. This site is user.sgit.ai, the first of the two, chosen on 21 October 2026 (N1 on the comms page); api.user.sgit.ai is the name its client code would take. A billing part that stands on its own at billing.sgit.ai stays an option. It is not yet in the network directory on sgit.ai; adding it is the Cartographer's prompt there, and T6 here.

What being part of a network costs

Every entry above is a link this site depends on and does not control. A sibling that has not shipped a page this site references is a fact about the network's build order, not a defect here, and it is checked rather than assumed: admin/build/check_siblings.py reports on it as a tool run by hand before a release, never as a gate, because a sibling's outage should not turn this repository's build red for a reason nobody here can fix.

The account is a vault, and the user holds it: a passkey opens a door, the door opens a master, the master holds the keys, and the user's browser keeps the record and the meter. No sign-in to the site, no account database, no server of ours that can read a thing. CC BY 4.0, part of the sgit.ai network.
