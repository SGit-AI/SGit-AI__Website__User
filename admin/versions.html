Release history

Every push to the release branch is a minor release, tagged automatically from one version file that has to agree with the release commit's subject before the tag exists. How the pipeline does it.

VersionDateWhat shipped
v0.1.1 21 Oct 2026 The site is user.sgit.ai. The project lead answered N1: the host is user.sgit.ai, the first of the two names the billing article proposed, mapped to this repository with GitHub Pages. v0.1.0 was built as users.sgit.ai and its deploy never completed, so nothing was ever served under the old name. Renamed everywhere: the CNAME, every canonical and og:url, the brand in the nav and footer, the sitemap, both text twins, and the lab, whose relying party and PRF input now follow the new host, SHA-256("user.sgit.ai/door/v1"). A passkey made for one host does not answer another, which is why this had to land before anyone made one. On comms, N1 is marked answered and the two tasks that waited on it, vendoring the vault library and joining the network directory, are unblocked.
v0.1.0 21 Oct 2026 The site, first release: the account model, the ten workflows, the billing proposal, and a lab that derives a door on this origin. Built from the newsroom's articles and build notes on the client-side user workflows, read the same day, and sgit.ai's guidance for *.sgit.ai sites. The account model: the pieces, the derivation, what is in each vault, a door per path, every key and who holds it, the four parties, security said plainly, and where PRF works. Ten workflows, each with what the user does, what the browser does, what leaves it, and a status chip tied to a newsroom release or an article. Billing: the user keeps the meter, set out as the proposal it is, with its open questions kept. The lab: six cards on this origin, a passkey for users.sgit.ai with PRF, the bytes, the door's address and sgit's keys, a recovery code, and the newsroom's test vectors run through this site's vendored copy of the derivation, which a Node test also checks; it writes nothing to any server. What this site ships keeps the honest column; the sources keep the provenance; comms puts six questions to the project lead, the first of them the site's own name. The gate enforces the passkey design's one rule, no third-party script on any page, beside the house checks. Plus the agent surface: llms.txt, llms-full.txt, a markdown twin of the front page, a sitemap.

user.sgit.ai

The account is a vault, and the user holds it: a passkey opens a door, the door opens a master, the master holds the keys, and the user's browser keeps the record and the meter. No sign-in to the site, no account database, no server of ours that can read a thing. CC BY 4.0, part of the sgit.ai network.
