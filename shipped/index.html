Lab-proven, once

  • A door created at its derived address on a real vault server, opened again the way a new device would, and its file deleted. The newsroom's lab, 11 and 12 October, with one Google Password Manager passkey and one iCloud Keychain passkey, across a Mac, an iPad and an iPhone.
  • The derivation agrees with sgit's Python byte for byte, from a fixed test vector and from live bytes. This site's lab runs the same vectors through its own copy of the code, and a Node test does the same before a release.
  • The same passkey gave different bytes by the QR path than by the platform path, consistently. That finding is why the design has a door per path.

Designed, not built

  • Key pairs in the master: a signing pair and an encryption pair, made at random on the first device, with the public halves published where the share page and the subscribe lane need them.
  • Adding a door by the other path while unlocked, with no key typed, offered in the first week as add your phone by QR.
  • Retiring a device and rotating the master's key; retiring a master in the order the article gives.
  • Several passkeys for several roles, as several masters, chosen in the provider's own picker.
  • Automatic sync on a timer or on leaving a page, as a setting; pruning local records the vault already holds.
  • The handover of a read key from a master to an agent, for one vault.

Proposed, with open questions

  • One billing vault per user, two signed writers, credit now and validated later, Stripe reconciled from the admin's browser, a credits API and one light check at the upload server. 21 October 2026. Nothing built; the Stripe flow untested.
  • Messaging-FS: a messenger between vaults on append lanes and PKI. The transport exists; the schema and the commands do not.
  • AWS from the vault: a temporary AWS session kept in a vault for one session, the browser doing the work. Nothing built; the name not decided.
  • One account across sites: a key hub, or Related Origin Requests. Later.

users.sgit.ai

The account is a vault, and the user holds it: a passkey opens a door, the door opens a master, the master holds the keys, and the user's browser keeps the record and the meter. No sign-in to the site, no account database, no server of ours that can read a thing. CC BY 4.0, part of the sgit.ai network.
